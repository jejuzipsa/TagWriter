  - loads that card's read-only detail view,
  - selects/highlights the matching tree item.

IMPLEMENTED — CARD DATA / CHARACTER
- Replace the current generic description/aliases-only card UI with type-specific fields.
- Character creation popup fields:
  - 이름
  - 나이
  - 생일
  - 나이 기준일 (the in-story date on which the displayed current age is based)
  - 출생년 (automatically calculated from age + birthday + age-reference date)
  - 가족 (free text; examples: "부X 모O 형3, 누나1" or "김철수(형)")
  - 학력 (free text; examples: "고졸", "서울대")
  - 메모 (multiline)
  - 태그 (additional aliases only)
- Character name itself is always an automatic/default tag. The user does not have to repeat the name in the tag field.
- Additional tags/aliases are entered in one field separated by commas (example: `민수, 김민수, 민수 씨`). Line breaks are also accepted for compatibility/paste, but the editor displays aliases comma-separated.
- If the character name changes, the automatic name tag changes with it; manually entered additional tags remain.
- Internal linking must continue to use the card's stable ID, not the visible name/alias.

IMPLEMENTED — CARD DATA / LOCATION
- Location card fields:
  - 이름
  - 메모 (multiline)
  - 태그 (additional aliases only)
- Location name itself is an automatic/default tag.
- URLs written inside memo text should be recognized in the read-only card view and rendered as clickable links.
- Clicking a memo URL opens it in the Windows default external browser (Chrome if Chrome is the user's default), not an embedded TagWriter browser.
- Intended uses include Google Maps/Street View, reference photos, YouTube/video references, blogs/wiki/reference pages.
- Prefer the same URL-link behavior for memo fields on other card types as well.

IMPLEMENTED — CARD DATA / EVENT
- Rename "사건" card/category wording to "이벤트".
- Event card fields:
  - 이름
  - 메모 (multiline)
  - 태그
- Event cards are NOT manuscript auto-tagging targets.
- Event cards do NOT create automatic character/location/item relationships from manuscript co-occurrence.
- Event nodes still appear as available relationship-map nodes and can be connected manually.
- Event name/tags are therefore for card lookup/identification and manual relationship-map use, not automatic manuscript detection.

PENDING — ITEM
- Item remains a card type, but its detailed fields, manuscript auto-tagging behavior, and final category color have NOT been decided yet.
- Do not invent these decisions in the next implementation. Confirm them when the item card is designed.

IMPLEMENTED — TAG COLOR SYSTEM (ITEM COLOR UNDECIDED)
- Use separate dark/light colors so tags stay legible in both themes.
- Character / 인물:
  - Dark: #60A5FA
  - Light: #2563EB
- Location / 장소:
  - Dark: #F87171
  - Light: #DC2626
- Event / 이벤트:
  - Dark: #FBBF24
  - Light: #B45309
- Item color: undecided.
- Automatic name tags and manually entered additional tags use the same color for that card type.
- For manuscript tag highlighting, prefer the category text color plus a subtle low-opacity background rather than an aggressive solid highlight.
- Event tags are not highlighted automatically in manuscript text.

IMPLEMENTED — MANUSCRIPT AUTO TAGGING
- Character and Location names are automatic tags and their additional aliases are also manuscript-detection terms.
- Event must be excluded from the automatic occurrence/tag scanner.
- Current code still scans all cards; this must be changed during the card/tag refactor.
- Relationship/tag identity always resolves to the stable card ID even when the manuscript matched an alias.
- When showing a relationship or linked tag in UI, display the card's canonical name, not the alias that happened to match.
- In Normal manuscript mode only, detected Character/Location tags should be rendered as clickable inline text with category color, bold weight, and underline.
- Clicking a tagged name/alias selects the matching card and shows that card in CONTEXT.
- The 등장 view for the selected card should list every matching occurrence as chapter | scene | current line number, followed by the matching sentence/line text.
- Each occurrence row uses a text button labeled [이동] (not an arrow icon). Clicking [이동] opens the matching scene, scrolls to the occurrence, and moves focus/caret to that location; a brief highlight may be used so the destination is obvious.
- Do not persist raw line numbers as identity. Resolve navigation from stable card ID + scene ID + current text position/offset and calculate the displayed line number from the current manuscript text.
- Manuscript-paper mode must NOT enable inline tag styling, tag clicking, or occurrence-jump interaction. Tag interaction is a Normal-mode feature only.

PENDING — AUTOMATIC VS MANUAL RELATIONSHIPS
- Default relationship generation should be automatic from manuscript co-occurrence rather than requiring "related tags" fields inside cards.
- Intended automatic strength hierarchy:
  - same sentence = strongest local relation signal
  - same paragraph = medium relation signal
  - same scene = weaker relation signal
  - repeated co-occurrence across scenes accumulates relationship strength
- Exact numeric weighting formula is not fixed yet.
- Node size should NOT grow simply because the same pair occurs many times; node size is based on the count of unique connected nodes.
- Automatic relationship line style/color:
  - Dark: #94A3B8
  - Light: #64748B
  - visually quieter/thinner; frequency/strength may increase line thickness and opacity
- Manual relationship line style/color:
  - Dark: #C084FC
  - Light: #7C3AED
  - more prominent solid line, slightly thicker than automatic
  - may carry a user-entered relationship label such as 남매, 근무지, etc.
- Keep color meaning fixed; represent automatic strength with thickness/opacity rather than changing to unrelated colors.
- Event has no automatic relationships; manual only.
- Item automatic relationship behavior remains undecided.

IMPLEMENTED — RELATIONSHIP MAP NODE WORKSPACE
- Current map is still simple fixed-position buttons and does NOT yet implement the approved workspace behavior.
- Split the relationship-map screen so the far-left side contains a dedicated "미배치 노드" tray/section.
- Newly created card nodes are added to the unplaced tray, arranged vertically from the top downward; new nodes append below existing ones.
- Do NOT immediately scatter new nodes across the graph as the current code does.
- Drag a node from the unplaced tray into the main relationship-map canvas to place/use it.
- Placed nodes can be freely dragged around the main map.
- Persist placed node X/Y coordinates in the novel/project JSON so reopening the project keeps the user's layout.
- Once a user has manually positioned a node, later automatic layout should not move it.
- A "return to unplaced" action is desirable so removing a node from the visible map does not delete the card.
- Relationship data exists independently of placement:
  - an unplaced node can still have relationships,
  - its lines simply are not drawn until both relevant nodes are placed.

IMPLEMENTED — RELATIONSHIP MAP NODE SIZE
- Node size grows with the number of UNIQUE connected nodes.
- Suggested base size is about 70 px and maximum size about 125 px; keep a hard maximum so a central character cannot consume the whole graph.
- Repeated co-occurrence with the same one node affects the relationship line, not the node's overall size.
- Category/node colors should follow the same character/location/event color system above; item color remains undecided.

IMPLEMENTED — CONNECTED TAGS AT BOTTOM OF CARD
- When a Character/Location/etc. card has map relationships, show a read-only "연결된 태그" section at the very bottom of the card detail view.
- This section is generated from relationship data and cannot be directly edited as a normal card field.
- Display each connected card using the connected card's canonical name and category color.
- Clicking a connected tag navigates directly to that card:
  - loads that card into right CONTEXT,
  - expands CONTEXT if collapsed,
  - selects the matching card in the left PROJECT tree.
- A relationship should appear here even if the connected node is still in the map's unplaced-node tray.
- Automatic/manual relationship type can be indicated subtly:
  - automatic: small slate indicator
  - manual: small purple indicator
  - optional tooltip "자동 관계" / "수동 관계"
- Do not replace the target card color with the relationship color; target tag color still represents the target card type.

REMAINING UNDECIDED / NOT IMPLEMENTED
- Item card:
  - detailed fields
  - final category/tag/node color
  - manuscript automatic-tagging behavior
  - automatic relationship behavior
  These remain intentionally unimplemented because the decisions were never finalized.
- Automatic relationship generation:
  - co-occurrence detection structure is agreed (same sentence > same paragraph > same scene, repeated scenes accumulate),
  - but the exact weighting/strength formula is still undecided,
  - so TagWriter does not yet create/update automatic relationship edges from manuscript co-occurrence.
- Manual relationship authoring is implemented:
  - click the first node to make it the relationship anchor,
  - hold Ctrl and click a second node to toggle a manual relationship,
  - if no manual edge exists, create one; if that manual edge already exists, remove it,
  - the current anchor is shown with a thicker purple border,
  - automatic edges are not deleted by this manual toggle.
- Everything else from the previous handoff plan has now been implemented through 0.0.7.4.

RECOMMENDED NEXT DECISIONS
1. Decide Item fields, Item color, and whether Item participates in manuscript auto-tagging/automatic relationships.
2. Decide the automatic relationship weighting formula for sentence / paragraph / scene co-occurrence.
